# System

Source: `src/extractors/system/`

## Overview
- Scope: Windows and macOS system artifacts — registry hives, Jump Lists, file system enumeration, DPAPI credential decryption, and macOS property list parsing.
- Extraction: Copy system artifact files (hives, Jump Lists, plists, DPAPI key material) into case output with manifests.
- Ingestion: Analyze hives with rules into `os_indicators`; parse Jump Lists/LNKs into `jump_list_entries` and `urls`; enumerate file systems into `file_list`; decrypt DPAPI-protected browser secrets; parse macOS plists into `os_indicators`.

## Extractors
### SystemRegistryExtractor
- Purpose: Extract Windows registry indicators for forensic analysis (e.g., system info, startup, network profiles).
- Extraction (source): Offline registry hives discovered via glob patterns in evidence (SYSTEM, SOFTWARE, SAM, SECURITY, NTUSER.DAT, UsrClass.dat).
- Ingestion (transform + store): Applies registry rule targets to exported hives; normalizes findings and inserts into `os_indicators`.
- Outputs: `manifest.json` plus copied hive files under `hives/`; ingestion summary `ingestion_registry.json`.
- Dependencies: `regipy` required for ingestion; extraction does not require it.
- Notes: Uses rule set loaded from `rules.py` via `load_registry_rules`; supports purge-by-evidence and run_id cleanup.

### SystemJumpListsExtractor
- Purpose: Extract Jump List and Recent Item artifacts, including browser URLs and file targets.
- Extraction (source): Jump List and Recent Item files from user profile paths (AutomaticDestinations, CustomDestinations, standalone `.lnk`).
- Ingestion (transform + store): Parses OLE/Custom Jump Lists and LNKs, derives titles/URLs, inserts into `jump_list_entries` and `urls`.
- Outputs: `manifest.json` plus copied Jump List/LNK files in the extractor output directory.
- Dependencies: Requires `olefile` for extraction and ingestion; uses AppID registry to classify browser Jump Lists.
- Notes: Clears prior Jump List entries and related URLs for the evidence before ingestion to avoid duplicates.

### SystemFileListExtractor
- Purpose: Enumerate file system entries from evidence images using SleuthKit or import from CSV.
- Extraction (source): Full partition file listings generated by SleuthKit tools (`fls`, `mmls`) or imported from user-provided CSV files.
- Extraction (behavior): Runs SleuthKit `mmls` to discover partitions, then `fls` to enumerate files per-partition; writes bodyfile output; alternatively imports pre-generated CSV file lists.
- Ingestion (transform + store): Parses bodyfile output into `file_list` table with columns for filename, path, size, timestamps (modified/accessed/changed/created), inode, partition index, and deleted flag.
- Outputs: Bodyfile output and/or CSV imports; `file_list` table entries used by many downstream extractors for multi-partition file discovery.
- Dependencies: SleuthKit binaries (`fls`, `mmls`, `icat`) resolved via bundled binaries or system PATH.
- Notes: The file_list table is a prerequisite for multi-partition discovery in many browser extractors; supports both E01 images and mounted filesystems.

### SystemDpapiDecryptExtractor
- Purpose: Decrypt Windows DPAPI-protected browser secrets (passwords, cookies, credit cards) offline.
- Extraction (source): Windows registry hives (SYSTEM, SAM, SECURITY) for key material, DPAPI master keys from Users/*/AppData/Roaming/Microsoft/Protect/<SID>/<GUID>, and Chromium Local State files from all supported browsers (Chrome, Edge, Brave, Opera, Vivaldi).
- Extraction (behavior): Copies hives (or reuses from registry extractor), master key files, and Local State JSON into case output with manifest.
- Ingestion (transform + store): Full decryption pipeline — (1) extract boot key from SYSTEM hive, (2) extract NTLM hashes from SAM, (3) attempt master key decryption via password/NTLM hash/empty password/DPAPI_SYSTEM keys, (4) unwrap Chromium v10 AES keys from Local State, (5) batch decrypt v10-encrypted blobs; inserts into `windows_users`, `dpapi_master_keys`, `chromium_app_keys`; updates existing `credentials`, `cookies`, `credit_cards` with decrypted values; writes `decrypt_audit` trail.
- Outputs: Copied hives and key files; decrypted credential/cookie/credit card values; full decrypt_audit trail.
- Dependencies: `regipy` required for registry hive parsing; Windows SYSTEM/SAM/SECURITY hives must be extractable.
- Notes: Two-phase workflow — extraction collects raw files, ingestion performs CPU-intensive cryptography; config options (auto_sam, user_password, decrypt flags) control decryption attempts; all attempts logged in decrypt_audit; supports multi-user evidence with fallback key matching.

### SystemMacosPlistExtractor
- Purpose: Extract macOS system artifacts from property list (plist) files — system configuration, installed applications, user activity, and quarantine events.
- Extraction (source): 15 plist patterns: SystemVersion.plist, SystemProfiler preferences, NetworkConfiguration, GlobalPreferences, Application Info.plists, package receipts, LaunchServices, RecentItems, Finder preferences, Spotlight preferences, QuarantineEventsV2, and default browser preferences.
- Extraction (behavior): Scans evidence for matching plist files (binary and XML); copies to case workspace preserving directory structure relative to evidence root.
- Ingestion (transform + store): Parses plists into typed `os_indicators` — OS version, hardware info, timezone/locale, installed applications, package install receipts, URL scheme handlers, recent documents/servers, Finder sidebar entries, Spotlight search history, quarantine events (downloaded files with referrer URLs), and default browser; all indicators stored with provenance="macos_plist" and detailed extra_json metadata.
- Outputs: Copied plist files; os_indicators entries with 12+ indicator types.
- Dependencies: Python stdlib `plistlib` (always available); QuarantineEventsV2 is SQLite (special case parsed inline).
- Notes: Quarantine events are high-value forensic data showing downloaded files with timestamps and referrer URLs; Spotlight metadata reveals search history; provenance tracking links all indicators to source files.

## Patterns
- File/path patterns: Registry hive globs under `Windows/System32/config/*`, `Users/*/NTUSER.DAT`, `Users/*/.../UsrClass.dat`, and legacy `Documents and Settings` paths; Jump Lists under `Users/*/AppData/Roaming/Microsoft/Windows/Recent/{AutomaticDestinations,CustomDestinations}` and `Recent/*.lnk`; DPAPI master keys under `Users/*/AppData/Roaming/Microsoft/Protect/<SID>/<GUID>`; Chromium Local State in browser User Data directories; macOS plists under `/Library/`, `Users/*/Library/Preferences/`, and `System/Library/CoreServices/`.
- Registry/OS patterns: Rule targets include key paths such as `Microsoft\\Windows NT\\CurrentVersion`, `...\\Run/RunOnce`, `...\\NetworkList\\Profiles`, and `ControlSet001\\...` in SYSTEM/SOFTWARE hives.
- Notes: Patterns are case-insensitive via explicit glob variants in registry hive scanning; macOS plist discovery uses both absolute and relative path forms for multi-partition support.
