# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- Opening a case no longer checks the external tools' versions for every evidence. Before, each evidence tab started about 56 `--version` subprocesses on the GUI thread (about 1.2 s per evidence). Each tool's version is now checked once per session, and checked again when its path or executable changes, or after **Refresh All**, **Set Custom Path** or **Reset to Auto** in **Preferences → Tools**. Foremost and Scalpel image-carving runs (Media extractors) still check the version again before they start, so the run manifest records the version that ran. With 20,000 URLs per evidence, the window is blocked while opening the case for 0.4 / 1.4 / 2.1 s instead of 1.6 / 6.2 / 12.3 s (1 / 4 / 8 evidences). Measured with the opt-in benchmark `tests/gui/app/test_case_open_benchmark.py` (#70).
- URLs tab: the grouped view (**Group by domain**) now covers every matching URL instead of only the first 10,000, and no longer blocks the window. Domains are listed alphabetically, 500 at a time, with exact URL counts. Domains that differ only in letter case form one group, like the Domain dropdown, and URLs without a domain are grouped under **(no domain)** at the end. A domain's URLs load in the background only when you expand it, 500 at a time and in the table's order. **Load more…** rows load the next domains or URLs, and a failed load can be retried from its row. Expanded domains stay expanded after a refresh or tagging. Loaded URLs of collapsed domains are kept up to 5,000 URLs. With 1 million URLs, the first domains appear after 0.1–0.3 s and an expanded domain's first URLs after about 50 ms, with the window blocked for at most 40 ms. Before, the window was blocked for 1.4–2.3 s and only the first 10,000 URLs could be reached. Measured with 5 and about 100,000 domains (2% of URLs without a domain) using the opt-in benchmark `tests/gui/app/test_urls_grouped_benchmark.py` (#64).
- Cases with several evidences open much faster and stay responsive. Evidences you have not shown yet no longer read data, count anything or start background work: each sub-tab (Download counts, Browser Inventory, File List, Extractors status, Tags, Reports, Screenshots, Audit) loads the first time it is shown. With 1 million URLs per evidence, the window is blocked while opening the case for 1.5 / 6.1 / 12.1 s instead of 4.9 / 26.2 / 72.3 s (1 / 4 / 8 evidences), and background work after opening ends after 1.6 / 6.3 / 12.8 s instead of 16 s / 3.9 min / more than 10 min, using 0.6 / 1.9 / 3.9 instead of 18 / 749 / 4,017 CPU seconds; memory after opening 8 evidences is 488 MB instead of 1,004 MB. The Overview counts load in the background while the Overview is shown (`Loading…`, `—` on error) and are remembered per evidence until something changes them, so switching back to an evidence shows them at once. The URLs tab shows its first rows without waiting for the filter dropdowns (about 50 ms instead of 0.4–0.7 s); the dropdowns load in the background, keep your selection when they reload, and are reloaded after ingestion, tagging, deduplication and list matching. Opening another case or closing an evidence tab stops the background work of all its sub-tabs. Measured with the opt-in benchmark `tests/gui/app/test_case_open_benchmark.py` (#63).
- URLs tab: text search for rare text is much faster on large evidence. For rare or absent text, the total and first page now take milliseconds instead of about 0.15–0.3 s and 0.4–0.65 s on 1 million URLs, and instead of about 2–3.5 s and 4–10 s on 10 million URLs. A search index (SQLite FTS5 trigram) is built in the background the first time the URLs tab is shown for an evidence, and again for new URLs after ingestion. A status next to the Search button shows its progress. Search results, their order and totals are unchanged: URLs not indexed yet, one- and two-character searches, and common text are searched without the index. The build pauses when you leave the URLs tab and while a case export runs. When a build that indexed URLs finishes, the shown table page is reloaded and the total recounted (beyond page 1, row numbers are then hidden until you return to page 1). Case export waits for running builds to stop, and is not started if one is still finishing. If SQLite lacks FTS5 trigram support, search works as before. Evidence migration 0006 adds the index state. The index takes about 50–110 MB per million URLs, depending on URL length; building it takes about 10–40 s per million URLs on 1 million URLs and about 13 minutes for 10 million. Adding URLs costs nothing extra; deleting already-indexed URLs (re-extraction cleanup, deduplication, purge) is about 1.5–1.8 times slower on 1 million URLs and about 3.4 times slower on 10 million. Each build session that indexes URLs is recorded in the evidence process log; it does not change the evidence's "Last Extraction" time. Deleting URLs by run or by evidence now reports only deleted rows (#62).
- URLs tab: filtering by a single source is fast again for sources whose URLs have no First Seen time (e.g. carved URLs). Evidence migration 0005 extends the source index with First Seen. The index is rebuilt once when an existing case is opened. The domain dropdown now lists domains that differ only in letter case (`Example.COM`, `example.com`) as one entry, whose count matches the URLs it shows. Domains with equal counts appear in a fixed order. When you return to the URLs tab after changing tags in the Tags tab (rename or merge), the total is recounted without having to change pages (#67).
- URLs tab: fixed editing an **Occurrences** cell, which replaced the URL's tags with the typed value. Occurrences is now read-only, and the **Tags** cell is the editable column again. An inline tag edit recounts tag-filtered totals. The grouped view now shows each URL's existing tags, so editing them no longer starts from an empty cell and drops tags. Inline tag edits no longer remove a tag when only its letter case changes, and no longer split tag names that contain a comma. The tag filter now matches the selected tag exactly (ignoring case), and the URL text search matches `%`, `_` and `\` literally instead of as wildcards (#66).
- URLs tab: the first rows no longer wait for the total count. The exact total loads separately; the counter shows it as pending (`of … URLs (counting)`) until it is known. It is cached per filter, so Previous/Next does not count again. Paging uses a stable cursor order: First Seen newest first, URLs without a timestamp last, ties by ID. Pages are smaller and selectable (default 500 rows, remembered). The domain dropdown is now an exact, case-insensitive match, and a new "Domain contains" field provides literal substring search. Evidence migration 0004 adds an index for exact-domain browsing. CSV export reads rows in cursor batches; its output is unchanged (#61).
- URLs tab: the flat view's initial load, filter changes, Previous/Next and refresh now run in a cancellable background worker. Stale requests are interrupted inside SQLite and their results are discarded. Untagged URLs no longer trigger per-row tag lookups, and refresh reloads only the visible view (#60).
- Add a first-class Firefox Browser Config extractor for curated `prefs.js` and `user.js` settings with source-distinct ingestion into `browser_config` (#58).
- Add a first-class Chromium Browser Config extractor for curated `Preferences` and `Local State` settings (#57).
	- Note: older case workspaces ingested with the previous Chromium Extensions side-effect may still contain those historical `browser_config` rows until the case is intentionally cleaned or reprocessed.
- Add a read-only Browser Config subtab to Browser Inventory for filtering and inspecting stored `browser_config` evidence rows (#56).
- Fixed Chromium Media History playback parsing when SQLite rows are read via `sqlite3.Row`, including databases with `playback.origin_id` joined to the `origin` table (#31).
- Add app_execution, browser_history and installed_software to tagged summary export.
- Route Tag Summary `download`/`downloads` tags to the investigator downloads table as **Downloaded files**, distinct from browser download artifacts.
- Add embedded thumbnails for tagged images and image reference-list/hash matches in Tag Summary XLSX exports.
- Harden report and appendix image thumbnails: sources must resolve under the selected evidence workspace, generated thumbnails are embedded inline in report output, stale cache files are not trusted as report-visible evidence, and Pillow/optional pillow-heif rendering uses the shared thumbnail safety limits.
- Harden image/download/screenshot report HTML rendering by enabling Jinja autoescaping for evidence-derived fields.

## v0.3.8-beta - 2026-05-07

- Added batch folder import for URL reference lists with shared metadata and conflict handling.
- Removed the unused SQLite Hash DB preferences and rebuild workflow while keeping text hash-list matching.
- Removed deprecated YAML Rules preferences and internal rules_dir plumbing.
- Fixed `NameError: name 'normalized_logical_path' is not defined` in `chromium_sessions` extractor's `_collect_url_data()`, which caused all session files to be marked `error` in `browser_cache_inventory` and silently skipped URL cross-posting to the `urls` table (#55).
